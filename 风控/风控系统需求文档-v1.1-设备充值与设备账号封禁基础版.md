# 风控系统需求文档 v1.7 - 设备充值与设备账号封禁基础版

> 基于《风控系统需求文档 v1.0》补充。  
> 本版整理基础改造范围：充值封禁从账号维度改为设备维度、三方充值链接与两个问号指引、设备/IP 注册限制、主播设备登录限制、后台设备/IP 三个核心页面，以及关联账号、登陆 IP、封禁/解封、白名单、历史记录和删除账号等完整弹窗链路。

---

## 1. 变更总览

| 模块 | v1.0 现状 | 本次调整 |
|---|---|---|
| 设备注册限制 | 一个设备最多注册 3 个账号 | 改为一个设备最多注册 2 个账号 |
| IP 注册限制 | 一个 IP 最多注册 5 个账号 | 保持 5 个，不按身份筛选，仅统计注册数量 |
| 主播设备登录限制 | 一个设备只能登录一个主播账号 | 保持限制，补充公会长也按主播身份处理 |
| 主播身份定义 | 加入公会的账号 | 保持不变：加入公会才算主播；公会长也纳入主播类身份 |
| 充值封禁 | 按账号统计充值金额 | 改为按同设备聚合充值总金额 |
| 充值统计口径 | Google、Apple | 保持不变：仅 Google、Apple 计入设备充值封禁金额 |
| 三方充值链接 | 无额外身份校验页面要求 | 增加 Wechill ID + 验证码校验页面，样式见本文图片 |
| 后台能力 | 查看设备关联账号、删除账号 | 强化为可查看设备关联账号、登陆 IP 记录，并可操作删除关联账号 |
| IP 白名单 | v1.0 未明确 | 新增 IP 白名单，不限制该 IP 下注册数量；白名单 IP 登录总数默认 8 个，可配置 |
| IP 封禁列表 | v1.0 未明确 | 新增 IP 封禁列表，独立展示 IP 封禁、解封、证据和历史封禁次数 |
| 存量数据兼容 | v1.0 未明确 | 新规则上线后对存量设备/IP 生效；历史超限不自动删除，但后续注册/登录/充值按新规则拦截 |

## 2. 充值封禁改造

### 2.1 现有规则参考

现有充值限额/封禁规则如下图，原逻辑按 `user_id` 查询用户充值封禁配置与官方充值总额。

![现有充值封禁规则详情](risk_device_basic_assets/current_recharge_rule_detail.png)

### 2.2 新规则目标

原逻辑按账号累计充值金额，用户可通过同一设备切换多个账号继续充值。本次改为按设备统计：

```text
同一设备下账号 A / B / C
    ↓
Google + Apple 成功充值金额合并累计
    ↓
按设备总金额判断充值限制档位
    ↓
命中后，该设备下所有账号继续充值均受限
```

### 2.3 统计口径

| 项目 | 规则 |
|---|---|
| 统计对象 | 设备，建议使用服务端稳定设备标识，如 `risk_device_hash` / `device_id` |
| 计入渠道 | Google、Apple |
| 不计入渠道 | 三方充值/H5 充值暂不计入本次设备充值封禁金额，仅做链接身份校验 |
| 金额单位 | 沿用现有美元口径 |
| 计入订单 | 首次支付成功的 Google/Apple 官方充值订单 |
| 退款/拒付/补单 | 不调整设备充值封禁金额：退款或拒付不扣减，补单不新增或回补统计金额 |
| 查询时机 | 用户发起充值准备/下单前 |

### 2.4 档位规则

沿用现有 `limit_type` 含义，但判断金额从账号总额改为设备总额。

| `limit_type` | 含义 | 设备维度判断 |
|---:|---|---|
| 0 | 无限制 | 正常放行 |
| 1 | 限额 200 美金 | 本次充值金额 + 当前设备官方累计充值金额 > 200 时拦截 |
| 2 | 限额 1000 美金 | 本次充值金额 + 当前设备官方累计充值金额 > 1000 时拦截 |
| 3 | 已限制充值/充值封禁 | 当前设备下所有账号充值直接拦截 |
| 其他/无配置 | 全局默认限制 | 沿用现有全局 500 美金判断，改按设备总额计算 |

### 2.5 白名单与优先级

| 白名单类型 | 是否影响本规则 | 说明 |
|---|---|---|
| 充值账号白名单 | 是 | 指定账号可跳过充值封禁，但仍建议记录设备累计金额 |
| 充值设备白名单 | 是 | 指定设备下账号可跳过设备充值封禁 |
| IP 白名单 | 否 | 只影响 IP 注册/登录数量限制，不影响充值封禁 |
| 设备注册白名单 | 否 | 只影响注册限制，不默认影响充值封禁 |

白名单必须记录操作人、原因、有效期和操作日志。基础版建议先不做全局免风控白名单，避免误把注册、登录、充值、收益等规则一起绕过。

### 2.6 后台能力

| 能力 | 要求 |
|---|---|
| 查询设备充值状态 | 支持按设备 ID、用户 ID 查询当前设备累计充值金额与限制状态 |
| 调整设备充值封禁 | 可设置未限制、200 美金、1000 美金、全面限制充值 |
| 设备充值解封 | 只恢复充值能力，不自动解除账号封禁、设备登录封禁、收益/提现限制 |
| 设备充值日志 | 记录自动触发、人工调整、解封、白名单变更 |
| 设备关联账号 | 可查看该设备下所有账号、主播身份、充值金额、账号状态、最近登陆时间 |
| 登陆 IP 记录 | 可查看账号历史登陆 IP、最近登陆时间、登陆状态和 IP 所在国家 |

## 3. 三方充值链接身份校验

### 3.1 需求说明

三方充值链接访问前增加身份校验页面，页面样式参考附件中的 LAMA 快充登录页，但品牌全部替换为 Wechill：

- 平台名称从 `lama` / `Lama` 改为 `Wechill`。
- 页面 logo 使用附件中的 Wechill 狮子图。
- 输入项从 `Lama ID` 改为 `Wechill ID`。
- 验证码发送文案改为在 Wechill App 内发送。
- 页面需要在 PRD 中以图片形式直接展示，客户端按图还原。

![Wechill 三方充值链接身份校验主页面](risk_device_basic_assets/wechill_recharge_identity_page.png)

页面字段说明：

| 字段/控件 | 展示与含义 | 交互要求 |
|---|---|---|
| 浏览器地址栏 | 展示 Wechill 官方充值域名 | 必须使用 HTTPS；域名需由客户端、运营和安全侧共同确认 |
| Wechill logo/名称 | 使用附件狮子 logo 与 `Wechill` 名称 | 全页面不得残留 `Lama`/`lama` 品牌信息 |

| 服务条款/隐私政策 | 跳转对应协议 | 使用 Wechill 正式协议链接，新窗口打开时保留当前输入状态 |

| 区域 | 内容 | 规则 |

### 3.5 完整交互与异常场景

| 场景 | 页面处理 | 服务端/安全要求 |
|---|---|---|
| 首次打开链接 | 先展示身份校验页，不直接进入支付页 | 每次充值会话生成短期、不可猜测的会话标识 |
| ID 为空点击发送 | 提示“请先输入 Wechill ID” | 不发送验证码请求 |
| ID 不存在 | 提示账号不存在或信息有误 | 不暴露该 ID 的其他账号信息 |
| 账号封禁/注销/不可用 | 禁止发送或禁止进入支付页 | 返回统一账号异常错误码并记录风控日志 |
| 验证码发送成功 | 提示已发送到 Wechill App，发送按钮倒计时 | 限制单 ID、单设备、单 IP 的发送频率 |
| 发送失败 | 提示稍后重试 | 区分系统异常与频率限制，前端不展示内部错误 |
| 验证码为空 | 提示请输入验证码 | 不提交支付跳转 |
| 验证码错误 | 提示验证码错误 | 连续错误达到阈值后短时锁定并记录风险事件 |
| 验证码过期/已使用 | 提示验证码已失效，请重新发送 | 验证码一次性使用，成功后立即失效 |
| ID 与验证码不匹配 | 校验失败，不进入支付页 | 验证码必须绑定 ID、充值会话和有效期 |
| 校验通过 | 跳转三方充值支付页 | 生成一次性支付授权，禁止仅靠前端参数绕过 |
| 重复点击 OK | 仅受理一次 | 服务端接口需幂等，避免重复创建支付会话 |
| 网络中断/页面刷新 | 提示重试或恢复未过期会话 | 不在 URL、日志或本地明文存储验证码 |

### 3.6 品牌、客户端与多语言要求

- 主页面、两个问号指引、Toast 和错误提示均需接入多语言，顺序为中文、英语、阿语、土语、印地语。
- 阿语页面需要支持 RTL；数字验证码、Wechill ID、域名保持从左到右显示。
- 页面是三方充值链接的身份校验，不改变 Google/Apple 充值封禁统计口径。
- 验证码必须通过 App 内消息或既有安全验证码链路发送，不在网页上暴露账号敏感信息。

## 4. 设备账号封禁与注册限制

### 4.1 单设备注册上限

**规则：一个设备最多注册 2 个账号。**

| 场景 | 处理 |
|---|---|
| 当前设备有效注册账号数 < 2 | 允许注册 |
| 当前设备有效注册账号数 >= 2 | 禁止注册 |
| 后台删除同设备账号后 | 有效账号数同步减少，可释放注册名额 |
| 设备标识缺失/异常 | 建议禁止注册或进入人工校验，避免绕过 |

计数口径：

- 统计同一设备下成功注册的有效账号。
- 后台删除账号后，设备注册计数和 IP 注册计数同步减少。
- 被封禁但未删除的账号仍建议保留在关联账号列表中，用于风控证据追溯。
- 设备注册计数与服务端稳定设备标识绑定，卸载重装或清理客户端缓存不得重置计数。

客户端提示：

| 触发 | 标题 | 文案 |
|---|---|---|
| 设备已注册 2 个账号后再次注册 | 注册失败 | 当前设备注册账号数量已达上限，请使用已有账号登录 |

### 4.2 单设备主播登录限制

**规则：一个设备只能登录 1 个主播账号，包括公会长。**

主播身份界定：

- 加入公会后才算主播。
- 公会长按主播类身份处理。
- 普通用户不触发主播设备登录限制，但仍受设备注册账号数限制。

登录判断：

| 场景 | 处理 |
|---|---|
| 当前账号不是主播/公会长 | 允许登录 |
| 当前账号是该设备已占用的同一主播账号 | 允许登录 |
| 当前设备未存在主播/公会长账号占用 | 允许登录并记录设备主播占用 |
| 当前设备已有其他主播/公会长账号占用 | 禁止登录主播账号 |

退出公会后是否立即释放设备主播占用尚未确定，需要评审确认采用“立即释放”还是“冷却期后释放”，并明确冷却时长。确认前不得由客户端自行清除占用记录。

客户端提示：

| 触发 | 标题 | 文案 |
|---|---|---|
| 当前设备已有其他主播/公会长账号 | 登录失败 | 当前设备已存在主播账号，一个设备仅支持登录一个主播账号 |

### 4.3 加入公会阶段校验

为防止普通小号登录后再加入公会绕过主播限制，加入公会时也需要校验同设备主播占用：

- 普通账号申请加入公会前，查询当前设备是否已有主播/公会长账号。
- 若已有其他主播/公会长占用，禁止加入公会或进入人工审核。
- 公会长邀请账号加入公会时，也需要校验被邀请账号当前设备是否已存在主播占用。

客户端提醒按操作角色区分：用户侧可以明确展示当前设备的主播占用原因；公会长侧不得暴露被邀请用户的设备关联、其他账号或主播身份信息，只提示该用户暂不符合加入条件。

| 操作角色与场景 | 展示方式 | 标题 | 文案 | 操作 |
|---|---|---|---|---|
| 普通用户主动申请加入公会 | 阻断弹窗 | 加入失败 | 当前设备已存在主播/公会长账号，一个设备仅支持一个账号加入公会 | 点击“确定”关闭，保留当前公会页面 |
| 普通用户接受公会邀请 | 阻断弹窗 | 加入失败 | 当前设备已存在主播/公会长账号，暂无法接受该公会邀请 | 点击“确定”关闭，邀请状态不变 |
| 公会长邀请受限用户 | Toast | 邀请失败 | 该用户暂不符合加入公会条件，无法发送邀请 | 展示约 2.5 秒后自动消失，不创建邀请记录 |

交互边界：

- 三个入口均以服务端校验结果为准，客户端不得只依赖本地设备状态判断。
- 用户主动申请或接受邀请失败时，不写入公会关系，不占用主播名额。
- 公会长侧 Toast 使用通用资格提示，不展示“同设备已有主播/公会长账号”等风险详情。
- 本组提醒用于“直接禁止加入”分支；若规则配置为进入人工审核，应改为“申请已提交审核/邀请对象待审核”，不得展示“加入失败”。

### 4.4 存量设备账号兼容

新规则上线后，对历史已经存在的设备账号关系立即按新规则判断，但不做自动删除、不批量清退历史账号：

| 场景 | 兼容处理 |
|---|---|
| 历史同设备已注册/登录超过 2 个账号 | 历史关联关系保留用于审计；后续该设备再次注册账号时按“最多 2 个账号”拦截 |
| 历史同设备已登录 5、6 个账号 | 上线后按新逻辑生效；以功能上线后首次成功登录的账号作为第一个正常登录账号，后续触发设备登录限制的账号展示客户端登录限制弹窗 |
| 历史同设备存在多个主播/公会长账号 | 以功能上线后首次成功登录的主播/公会长账号作为设备主播占用；其他主播/公会长账号在该设备登录时触发主播登录限制 |
| 受限用户处理 | 客户端展示登录限制弹窗，用户可主动联系官方；后台通过设备关联账号、封禁/解封、删除账号等能力处理 |
| 历史充值数据 | 同设备 Google + Apple 累计充值按设备重新聚合，不因历史账号数量超限而清空 |
| 卸载重装/清理缓存 | 继续使用服务端设备关联关系，设备注册账号数和设备充值累计均不清零 |

客户端样式要求：登录受限时复用本文 7.1 中黑金 App 弹窗样式，按钮、遮罩、底色保持一致；文案按触发原因区分设备账号限制或主播登录限制。

## 5. IP 注册限制与 IP 白名单

### 5.1 单 IP 注册上限

**规则：一个 IP 最多注册 5 个账号，不按身份筛选，仅统计数量。**

| 场景 | 处理 |
|---|---|
| 当前 IP 注册账号数 < 5 | 允许注册 |
| 当前 IP 注册账号数 >= 5 | 禁止注册 |
| 当前 IP 命中 IP 白名单 | 不限制该 IP 下注册数量 |

公共 Wi-Fi、运营商 NAT 等共享出口 IP 容易造成误伤。IP 注册规则作为辅助判断，处置时应优先结合设备规则；确认属于可信共享网络后，可通过 IP 白名单兜底。

客户端提示：

| 触发 | 标题 | 文案 |
|---|---|---|
| IP 已注册 5 个账号后再次注册 | 注册失败 | 当前网络环境注册账号数量已达上限，请更换网络后再尝试注册 |

### 5.2 IP 白名单

IP 白名单用于处理公会办公网络、官方测试网络、客服/运营网络等多人共用 IP 的场景。

| 配置项 | 默认值 | 说明 |
|---|---:|---|
| IP 地址 | - | 支持单 IP，是否支持 IP 段/CIDR 需研发确认 |
| 是否豁免注册上限 | 是 | 命中后不限制该 IP 下注册数量 |
| 白名单 IP 历史登录账号总数上限 | 8 | 按该 IP 历史成功登录过的去重用户 ID 统计，默认 8 个，可后台配置 |
| 生效时间 | 必填 | 建议设置有效期，避免长期无限放行 |
| 添加原因 | 必填 | 记录公会/测试/客服等用途 |
| 操作日志 | 必填 | 记录添加、修改、删除、过期 |

边界规则：

- IP 白名单只豁免 IP 注册数量限制，不豁免设备注册限制。
- IP 白名单不豁免同设备主播登录限制。
- IP 白名单不豁免设备充值封禁。
- 白名单 IP 下注册数、登录数、同设备数异常增长时，需要进入风控复核。
- 同一账号重复登录只计 1 个；历史登录账号总数不按自然日重置。
- 达到配置上限后，已计入的历史账号仍可登录，新账号首次通过该 IP 登录时触发限制。

口径说明：

- “白名单内 IP 限制的登录总数”统一按历史成功登录账号总数计算，即该 IP 下曾成功登录过的去重用户 ID 数量；默认上限为 8，可后台配置。

### 5.3 IP 封禁

IP 封禁用于处理 IP 注册账号超限、异常跨国登录、批量设备攻击等风险。

| 封禁类型 | 触发入口 | 处理逻辑 |
|---|---|---|
| 封 IP | IP 入口/登陆 IP 记录/IP 封禁列表 | 仅封禁对应 IP，不自动封禁账号或设备 |
| 封号封设备封 IP-慎用 | 设备列表/封禁弹窗 | 封禁该设备所有账号与当前设备，同时封禁目标账号最后一次登陆 IP |

封禁时间选项：`1h`、`6h`、`12h`、`1天`、`2天`、`3天`、`7天`、`永久`。

封禁证据为必填项，封禁理由下方需要提供“点击上传证据”。支持的文件类型、大小、数量、视频时长、存储和预览方式均需与研发确认；确认前不在产品文档中预设具体格式。

IP 解封时需要二次确认，可填写解封理由（非必填）；解封后写入操作日志。列表中的“解禁时间”只展示具体时间点，永久封禁未解封前展示 `-`，不展示“永久”。

## 9. 建议补充确认的遗漏场景

基础版建议在评审时确认以下边界，避免研发实现时口径不一致：

| 场景 | 建议处理 |
|---|---|
| 卸载重装/清缓存 | 不应重置设备注册账号数和设备充值累计 |
| 退出公会后是否释放主播设备占用 | 立刻释放，还是增加冷却期，冷却时长？ |
| 删除账号是否永久释放名额 | 基础版按“删除后释放”实现，但审计归档必须保留，防止反复删除重新注册 |
| IP 白名单登录总数口径 | 历史登录账号总数 |
| 三方充值是否未来计入充值封禁 | 本版不计入，仅做身份校验；如后续计入，需要补充订单回传和金额换算口径 |
| 退款/拒付/补单 | 不影响充值封禁金额的统计 |
| 公共 Wi-Fi/运营商 NAT | IP 规则容易误伤，应优先依赖设备规则和 IP 白名单兜底 |
| 存量超限设备 | 需确认“第一个正常登录账号”的取数口径：功能上线后首次成功登录 |
| 封禁证据格式 | 封禁弹窗要求必填证据，需确认支持文件类型、大小、视频时长、存储与预览方式 |
| 验证码规则 | 需确认验证码位数（目前 4 位）、120 秒有效期、发送冷却时间、单 ID/设备/IP 频率限制和连续错误锁定阈值 |
| 三方充值会话 | 需确认验证码通过后的支付授权有效期、幂等键、刷新恢复和重复提交处理 |
| 弹窗上下文带入 | 需确认从账号、设备、IP 不同入口进入统一封禁弹窗时的默认类型、对象 ID 和影响范围 |
