# HAWA「Invite Friends」活动产品梳理

> 调研时间：2026-07-23  
> 调研环境：Android（720 × 1600），已登录的零邀请测试账号  
> 调研范围：活动首页、奖励数据区、全部规则说明页；未触发分享、复制、充值、入会或开播等会改变账号/外部状态的动作。

## 1. 活动一句话

这是一个以**邀请新用户注册并完成首个有效体验**为入口、以新用户后续**充值**和**成为主播后的有效魅力收益**为持续贡献来源的邀请裂变活动。邀请人既获得一次性 Coins 奖励，也可获得与被邀请人长期价值相关的 Coins / USD 奖励。

## 2. 核心玩法

```text
邀请人获取专属 Friend Code / 邀请链接
        ↓
新用户通过链接注册，或注册后 7 天内填写 Friend Code
        ↓
建立一对一、长期有效的邀请关系
        ↓
新用户完成“有效邀请”门槛
        ↓
邀请人获得 500 Coins；并解锁后续充值 / 主播成长激励
```

### 2.1 身份与价值链

| 角色 | 关键动作 | 对邀请人的价值 |
|---|---|---|
| 邀请人 | 分享链接或邀请码、追踪进度 | 获得 Coins、充值贡献 Coins、主播成长 USD |
| 被邀请普通用户 | 注册后首次进入语音房并停留 | 成为有效邀请，触发新朋友奖励 |
| 被邀请的新主播 | 加入公会、完成首场有效直播 | 触发主播成长贡献奖励 |

### 2.2 关系建立规则

- 可通过专属邀请链接，或注册后填写 Friend Code 建立关系。
- Friend Code 的有效填写窗口为**注册后 7 天**。
- 同一新用户仅能绑定一位邀请人；关系建立后长期有效，当前不支持更换。
- 若链接和邀请码同时生效，系统优先采用有效的邀请链接。
- 链接过期但邀请码仍在有效期内时，仍可手动填码建立关系。

### 2.3 「有效邀请」门槛

**普通用户**须同时满足：

1. 首次进入语音房；
2. 在语音房达到有效时长，默认 **10 分钟**；
3. 账号及行为状态正常。

**新主播**须同时满足：

1. 加入公会；
2. 完成首个有效直播；
3. 单场有效直播达到平台要求，默认 **超过 30 分钟**；
4. 收益来源与账号状态正常。

## 3. 奖励机制

### 3.1 新朋友奖励（Coins）

规则页明确说明：每成功邀请 1 位有效新朋友，奖励 **500 Coins**，成功后即时入账，无需等待累计到里程碑。

| 有效邀请数 | 对应累计奖励 |
|---:|---:|
| 1 | 500 Coins |
| 50 | 25,000 Coins |
| 500 | 250,000 Coins |
| 1,000 | 500,000 Coins |

首页以 `1 / 50 / 500 / 1000` 的进度轨展示目标；测试账号显示 `Your Circle: 0/1000`，下一个目标为邀请 1 人并获得 500 Coins。

### 3.2 新用户充值奖励（Coins）

当被邀请新用户在关系建立后 **90 天内**，经官方渠道完成有效充值时，邀请人获得充值金额对应比例的 Coins。

| 90 天内充值额 | Coins 奖励比例 |
|---:|---:|
| 0–2,999 USD | 2% |
| 3,000–9,999 USD | 2.5% |
| 10,000 USD 及以上 | 3%，封顶 3,200,000 Coins |

约束：仅官方充值渠道有效；工资类/代理充值不计；退款、取消、异常或未确认订单不计。充值奖励默认有 **7 天确认期**。

### 3.3 新主播奖励（USD）

被邀请人加入公会并成为主播后，邀请人可按该主播产生的**有效 Charm Value 收益**获得 USD 奖励。规则限定只统计关系建立后 90 天内的有效收益。

当前规则表可见的月度目标档位为：

| 月度目标等级 | 奖励比例 |
|---|---:|
| Target 1–10 | 1.5%（有效 Charm Value 收益） |
| Target 11–19 | 3%（有效 Charm Value 收益） |

异常、审核失败或不满足规则的收益不计入。页面没有展示 Target 20 之后是否还有档位，因此不作推断。

| 区块 | 页面内容 | 产品作用 |
|---|---|---|
| 顶栏 | 返回、`Invite Friends`、`Rules` | 返回业务页；规则页承载复杂口径 |

| Share With Friends | 主 CTA | 调起系统/应用分享，扩大传播 |
| My Rewards | Coins、USD 的 Issued / Pending 余额；Recharge / Bag 入口 | 同时承接奖励进度与资产去向 |

| This Month’s Growth | 新朋友数、新主播数、当月 Coins / USD 的 Issued 与 Pending | 将邀请表现聚合为月度经营看板 |
| Top Contributors | 被邀请好友的充值与主播增长贡献 | 让邀请人识别高价值被邀请人 |

## 5. 规则说明页（信息架构）

![规则页完整长图：奖励概览、档位、邀请方式、关系规则、有效邀请条件及结尾声明](12-rules-long.png)

规则页的内容结构为：

1. 奖励总述与新朋友奖励；
2. 新用户充值奖励；
3. 新主播奖励；
4. 如何邀请；
5. 邀请关系规则；
6. 什么算有效邀请；
7. 新朋友 / 充值 / 主播奖励的结算说明与其他声明。

规则强调所有奖励由平台额外提供，不影响好友原有权益，也不从好友账户扣减；最终到账以账户、钱包或背包实际结果为准，且可能因审核、网络或维护延迟更新。

## 6. 产品设计解读

### 6.1 增长模型

- **低门槛首激励**：普通用户首次入房并停留 10 分钟即可使邀请有效，降低首批转化难度。
- **价值分层**：把即时拉新、90 天充值、90 天主播收益拆成三段，既做规模也做 LTV。
- **反套利口径**：一人一绑、链接优先、账号/行为正常、官方渠道、确认期与异常订单排除，减少刷量与退款套利。
- **可视化留存**：里程碑、当月看板、贡献排行和历史记录把“邀请后不可见”的链路变为可追踪资产。

### 6.2 当前体验的亮点

- 首页把“邀请码 + 分享按钮 + 奖励状态”集中在首屏，转化路径短。
- 两种绑定方式（链接 / Friend Code）覆盖跨平台分享和线下口头传播。
- 将 `Issued` 与 `Pending` 明确分开，能解释确认期和审核带来的到账延迟。
- 规则中给出了默认时长、90 天窗口、确认期与封顶，关键边界相对完整。

### 6.3 可继续验证 / 优化的点

1. **流程图右侧可见性**：当前 720px 屏幕上“Receive Rewards”有被容器裁切的观感；建议确认横向滚动/适配是否有明确提示，避免用户误以为流程未完整展示。
2. **奖励口径一致性**：规则声明“奖励费率和限制以页面展示为准”，但首页未直观看到充值/主播收益比例；可考虑在对应资产或信息图标中提供简版档位入口。
3. **状态解释的就近性**：`Pending` 的解释放在 `My Rewards` 信息图标中；月度增长另有信息图标。可评估是否在 Pending 数字旁增加更直接的确认周期提示。
4. **零数据空态**：`Top Contributors` 和 `Invite History` 目前只有一句说明。后续可验证在有 1–3 位有效邀请后，列表中的排序字段、刷新频率、隐私脱敏和跳转能力。

## 7. 已验证与未验证边界

| 项目 | 状态 | 说明 |
|---|---|---|
| 首页信息架构、零数据状态、信息浮层 | 已实测 | 见截图 |
| 全部活动规则文案 | 已实测 | 已逐段浏览规则页 |
| 邀请关系、有效邀请、奖励比例 | 已读取规则 | 规则声明，未通过真实交易/邀请触发验证 |
| 复制邀请码、分享面板与分享文案 | 未操作 | 避免对外分享与剪贴板状态变更 |
| 充值、背包、奖励到账、审核与排行榜非空态 | 未操作/未验证 | 避免资金、资产或账号状态变化 |
