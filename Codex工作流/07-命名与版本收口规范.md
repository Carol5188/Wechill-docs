# 命名与版本收口规范

目标：让 Codex 和人都能快速判断“哪个是当前版、哪个是历史版”。

## 推荐命名

```text
模块｜主题｜产物｜版本｜状态.扩展名
```

示例：

- `游戏房｜三方休闲游戏｜PRD｜v2.0｜当前评审版.md`
- `风控｜设备充值封禁｜后台原型｜current.html`
- `幸运礼物｜共享奖池｜PRD｜current.md`
- `公会｜薪资结算｜QA清单｜2026-06.md`

如果文件名需要兼容现有习惯，可以保留原名，但必须在 `PROJECT_INDEX.md` 里标记当前版。

## 状态词

| 状态 | 含义 |
|---|---|
| 草稿 | 结构未稳定 |
| 可评审版 | 可发给相关方评审 |
| 综合评审版 | 已合并多方意见 |
| 终审评审版 | 口径基本收口，仅剩少量确认 |
| current | 当前默认读取版本 |
| archive | 历史留档，不默认读取 |

## 版本规则

- 小修文案、字段、样式：`v1.1 -> v1.2`
- 规则口径或流程变化：`v1.x -> v2.0`
- 已评审但仍补漏：保留原大版本，状态改为综合评审版或终审评审版。
- 不确定是否最新时，不改旧文件，先更新 `PROJECT_INDEX.md` 标注候选。

## 收口动作

每次完成一个阶段后：

1. 更新模块 `PROJECT_INDEX.md` 的当前版候选。
2. 在旧版本旁写清楚“历史参考，不作为当前口径”。
3. 把待确认问题从正文散点收拢到索引里。
4. 下次任务先读索引，再读当前版文件。

## 不建议

- 不建议继续使用 `test`、`others`、`新版`、`最终最终版` 这种标题。
- 不建议在同一线程里长期混做 PRD、原型、多语言和归档。
- 不建议删除历史版本；先通过索引降权，确认无用后再归档。
