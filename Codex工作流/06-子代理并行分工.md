# 子代理并行分工

复杂任务不要让主线程一个人硬扛。主线程负责裁决和合并，子代理负责并行查漏。

## 推荐分工

| 子代理 | 适用任务 | 重点检查 | 输出 |
|---|---|---|---|
| 产品评审代理 | PRD、流程、页面 | 入口、角色、状态、边界、评审问题 | 缺口清单 + 建议补法 |
| 研发评审代理 | 接口、后台、HTML 原型 | 状态机、幂等、并发、版本兼容、回滚 | 技术风险 + 必补字段 |
| 风控/财务代理 | 幸运礼物、红包、公会、提现、充值 | 成本、预算、套利、误伤、合规、结算 | 风险点 + 裁决建议 |
| 文案/多语言代理 | 弹窗、Toast、活动页 | key、触发条件、英文/阿语、客服解释 | 文案表 + 冲突说明 |
| QA代理 | 交付前验收 | 测试用例、异常、权限、旧版本、截图引用 | 验收清单 + 阻塞项 |

## 主线程怎么下发

```text
你是【产品/研发/风控/文案/QA】子代理。
只读以下文件：【文件列表】。
不要修改文件。
请输出：
1. 发现的问题，按 P0/P1/P2 排序；
2. 必须补进文档/原型的内容；
3. 可以暂不处理但要记录的风险；
4. 你建议的最终裁决。
```

## 主线程怎么验收

- 子代理只给建议，最终口径由主线程合并。
- 如果子代理之间冲突，先写“冲突裁决表”，不要把冲突藏进正文。
- 子代理指出的问题要分为：立即修改、记录待确认、明确不采纳。
- 完成后更新对应 `PROJECT_INDEX.md` 的当前版和待确认问题。

## 适合立刻使用的场景

- 幸运礼物 RTP、奖池、风控降权。
- 游戏房强更、版本兼容、结算、三方回调。
- 公会薪资、自由/双周政策、历史欠款、提现账户。
- 风控封禁、解封、误伤、申诉、合规。
- 多语言文案、弹窗和客服解释口径。
